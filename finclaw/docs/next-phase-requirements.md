## 1. 产品定位

**智能财富顾问 → 客户经理营销陪伴助手**。系统服务于**客户经理**（业务使用者），为其营销提效；**客户只是数据实体，不是登录用户**，不涉及客户自助端。

核心价值主张：
- 对话即操作：核心业务动作均可通过自然语言对话调用 Agent 完成，操作台提供可视化呈现与快捷入口
- 确定性保障：合规审查、风险闸门、重试上限等强制约束始终由代码层掌控，不依赖 LLM 自觉
- 自动化提效：定时任务与批量初步方案生成，把客户经理从重复劳动中解放
- 自进化沉淀：业务经验（客户洞察、话术知识）在业务闭环中自动沉淀，反哺后续方案质量

## 2. 总体架构与关键技术实现

### 2.0 技术基调：Pi SDK 为底层框架（本阶段硬约束）

- **所有 Agent/LLM 能力一律基于 Pi SDK**（`@earendil-works/pi-coding-agent`）：主对话 Agent（会话管理、意图识别、工具调用、skill 加载）、方案生成的 LLM 叶子、批量洞察的 LLM 层、自定义工具注册（SDK 扩展机制）、Skill 加载（SDK 原生支持，Agent Skills 标准），均不引入第二套 LLM/Agent 框架。
- **Pi SDK 不覆盖的能力由宿主业务服务补齐**（不属于偏离，而是 Pi 边界之外）：定时调度、数据存储、确定性编排、合规规则。确定性编排为自建 TS 层（Pi 官方明确不支持 sub-agents，官方路径即自建/扩展，已调研确认）。
- **后续新增能力的技术评审标准**：凡涉及对话、生成、推理的能力，默认基于 Pi SDK 实现；如需偏离，须先说明理由并评审。

### 2.1 混合模式（Agent 自主 + 确定性编排）

主对话 Agent 具备**自主意图识别**能力，可调用两类能力载体：

| 载体 | 性质 | 适用 | 执行方式 |
|---|---|---|---|
| **Skill（指令包）** | 弱约束 | 方法论、分析框架 | LLM 读取指令自主执行 |
| **自定义工具** | 强约束 | 有确定性逻辑的业务动作 | TS 代码执行，LLM 仅传参数 |

**确定性边界（不可逾越）**：合规审查、风控闸门、审查重试上限等强制逻辑**只存在于 workflow 内部**，不向 Agent 暴露为独立可调工具，防止 LLM 跳过。

### 2.2 完整方案生成 = 固定 workflow

方案生成（generate / optimize）保持为**固定 workflow**（现有 workflow 引擎，其 LLM 叶子基于 Pi SDK），注册为自定义工具供 Agent 调用。确定性步骤（取数、风控、审查、重试）由自建 TS 编排层掌控，不因调用方式改变而放松。

### 2.3 编排与并发

- 批量并行 = **并发运行现有 workflow 引擎实例**（每客户一实例，限流并发），不引入社区多 Agent 插件
- 已调研 Pi 社区（`pi-subagents` 等）：均为 CLI 模式且面向动态协作场景，与本项目"同构并发 + SDK 嵌入"需求不匹配；架构预留调度抽象层，远期出现"多 agent 协作研究"类需求时再评估引入

## 3. 功能需求

### M1 双界面工作台

**总体功能**：同一页面分栏呈现"操作台 + 对话区"，操作与对话互为主从、双向联动。

**M1.1 布局**：同页分栏（操作台主区 + 对话区），可折叠切换；操作台选中对象（客户/方案）自动成为对话上下文。

**M1.2 操作台**
- 客户列表：现有客户栏演进，支持**任务筛选**（按任务策略类型 + 任务状态组合，见 M3.2）
- 客户画像摘要：选中客户展示画像摘要（行内硬数据只读 + 经理可编辑软数据 + 洞察标签，见 M4.1）
- 快捷按键区（四个主按键）：
  - `客户洞察` → 对全部管控客户触发批量洞察分析（见 M2.7）；单客户分析走对话
  - `市场分析` → 调市场分析能力
  - `生成方案` → 对当前选中客户触发方案生成
  - `批量任务` → 任务/提醒区入口
- 方案卡片区：已生成/保存的方案以**预览卡片**呈现
- 提醒区：操作台顶部，展示批量任务结果与待确认事项（见 M3.5）

**M1.3 对话界面**：历史对话气泡展示、流式输出；方案在对话中以 **Markdown 渲染**；所有能力均可通过对话自然语言触发。

**M1.4 方案双端渲染与同步**：对话中生成/优化方案 → 操作台卡片同步出现；点击卡片 → 对话展开详情继续优化。

> **关键功能解释**：方案是核心产出物，两端承担不同职责——对话侧重"生成与解释"，操作台侧重"对比与选择"，双端同步保证同一方案状态一致。

### M2 能力原子化

**总体功能**：将营销工作拆为原子能力，全部可被对话自然语言调用，核心能力有快捷入口。

**M2.1 能力矩阵（本轮范围）**

| 能力 | 载体 | 触发方式 | 输入 | 输出 |
|---|---|---|---|---|
| 客户分析（单客户） | 自定义工具 | 对话 | 客户 | 画像诊断 |
| **批量客户洞察** | **workflow（注册为工具）** | **快捷按键 / 定时 / 对话** | **全部管控客户** | **洞察标签 + 任务建议（双层）** |
| 产品推荐 | Skill | 对话 | 客户画像 + 合格产品列表 | 匹配推荐分析（含理由） |
| 市场分析 | Skill | 快捷按键 / 对话 | 产品池 + 知识库 | 定性市场分析（数据源可插拔） |
| 方案生成 / 优化 | workflow（注册为工具） | 快捷按键 / 对话 | 客户 + 指令 | 方案 + 合规报告 |
| 合规审查 | workflow 内嵌 | 不可独立调用 | — | — |
| 通用问答 | 主 Agent 原生 | 对话 | 自由文本 | 自然语言回答 |
| 知识库管理 | 现有功能增强 | 对话 / 界面 | markdown | 知识库内容 |

> **关键功能解释（载体选择逻辑）**：强逻辑（取数、规则过滤、确定性计算）→ 自定义工具，执行由代码保证；方法论（推荐分析框架、市场分析维度）→ Skill，由 LLM 依据指令执行。合规审查**刻意不暴露为独立工具**，保证其不可被跳过。

**M2.2 客户分析（单客户）**：取客户画像 + 产品池 + 知识库，输出结构化诊断（风险画像、资金结构、到期承接机会、沟通偏好）。确定性部分代码实现，分析叙事由 LLM 生成。

**M2.3 产品推荐（Skill）**：基于客户画像与**已过滤的合格产品列表**（过滤规则由代码完成）做匹配推荐，Skill 提供方法论，LLM 输出带理由的推荐分析。

**M2.4 市场分析（Skill，可插拔数据源）**：方法论由 Skill 承载；数据源设计为**可插拔接口**——本期空注入（占位，基于产品池做定性分析），预留外部市场数据 API 接入点，后续替换实现不影响 skill 主体。

**M2.5 方案生成 workflow**：现有 generate/optimize workflow 保留，注册为工具供 Agent 调用，内部执行完整编排（取数 → 风控闸门 → 生成 → 合规审查 → 重试）。

**M2.6 意图识别与路由**：Agent 对输入做意图识别，路由到工具/skill/通用问答；快捷按键本质是预置意图指令，与对话共用同一调用链。

**M2.7 批量客户洞察（workflow）** —— 本阶段核心新增能力
- **总体功能**：对客户经理**全部管控客户**做洞察分析，产出洞察标签与营销任务建议，驱动任务体系与客户筛选。
- **关键功能解释**：任务数据不应只靠硬编码规则，而应来自**对客户画像的洞察分析**——规则层保证不漏（确定性），LLM 层发现规则外机会（偏好变化、潜在需求），两层产出去重融合。区别于 M2.2 的单客户分析，本能力是批量、全量视角。
- **关键技术实现**：双层分析（规则层直写基础任务 + LLM 洞察层进待确认）；LLM 洞察层**复用方案生成的 Pi SDK 叶子模式**；**增量策略**控制成本（首次全量，后续只分析画像变更/新增/长期未分析的客户）；与定时链路衔接（洞察 → 打标 → 生成任务 → 批量方案）。

### M3 任务与自动化

**总体功能**：任务策略驱动的客户经营自动化——自动生成营销任务、按策略筛选客户、定时批量产出初步方案、提醒区集中呈现。

**M3.1 任务模型（营销策略体系）**
- 客户画像增加**任务**数据（与**特征标签**两套并存），任务带**策略类型**标识，来源分三层：规则层自动生成（直写）/ LLM 洞察建议（待确认后写入）/ 手动添加。
- **首批 12 项营销策略任务**（行业实践调研 + 决策人确认）：

| 类别 | 任务策略 | 触发条件（业务描述） |
|---|---|---|
| ① 资产事件 | 产品到期承接 | 存款/理财到期前提醒并承接 |
| | 风险评估到期 | 风险测评过期需重新评估 |
| | 大额资金异动 | 大额入账/转出后跟进回访 |
| | 临界客户升级 / 资产降级预警 | 资产达升级门槛或显著下降 |
| ② 关系关怀 | 生日祝福营销 | 生日当天祝福 + 定制配置建议 |
| | 沉睡客户唤醒 | 超期未联系/未交易 |
| | 节日问候 | 春节/中秋/国庆等 |
| ③ 生命周期 | 退休养老 / 子女教育金 / 财富传承 | 客户生命周期阶段匹配 |

> 暂缓项（后续评估）：新客破冰、政策/利率应对、行内活动邀约、新产品募集推荐、权益到期提醒。

**M3.2 任务筛选**：客户列表支持按**任务策略类型 + 任务状态**组合筛选，并可按"有待确认洞察"过滤。

**M3.3 定时任务（早 9 点，洞察-任务-方案一体化）**
- 触发链路（三级）：① 批量洞察（规则层 + LLM 增量层，产出任务与标签）→ ② 归并当日到期未完成的任务到客户粒度 → ③ 批量触发初步方案生成。
- **关键技术实现**：调度在业务服务内实现（定时任务框架），时间全局配置（默认早 9 点），支持手动触发。

**M3.4 批量初步方案生成**
- 按客户粒度每客户生成 1 套初步方案（多任务归并）；并发执行现有 workflow 实例（限流并发，防 LLM API 限流）；**单客户失败不牵连其他**，失败客户单独标记可重试。
- 方案**照常强制合规审查**：通过的进方案卡片，未通过的标"待处理"进提醒区。

**M3.5 提醒区**：操作台顶部集中呈现——批量生成结果、审查待处理、**洞察标签/机会任务待确认**、洞察分析完成通知；点击直达对应客户视图。

### M4 自进化沉淀

**总体功能**：业务经验在业务闭环中自动沉淀，反哺后续方案质量。分双视角：**客户视角**（洞察标签）与**客户经理视角**（个人知识库）。

**M4.1 客户标签与字段权限**
- **标签**语义：客户经理对特定客户营销过程中的独特看法（偏好、喜好、沟通习惯等），非行内字段。
- 画像字段三类权限：**行内硬数据**（姓名、资产、风险等级等行内收集信息，只读）；**经理软数据**（偏好、标签、任务等，可编辑）；**派生数据**（系统沉淀的洞察标签，经理确认后生效）。

**M4.2 客户洞察沉淀**
- 触发时机：客户经理表示"方案被客户接受"后（对话自然语言或卡片按钮双通道）。
- 流程：LLM 从对话上下文提取洞察 → 进**待确认区** → 经理一键确认（写入标签）/驳回。批量洞察（M2.7）与方案接受（M4.2）共用待确认区与写入通道。

**M4.3 个人知识库沉淀**
- 触发时机：最终方案优化敲定后（对话或卡片按钮）。
- 沉淀内容：从最终方案与优化过程提取可复用经验（话术模板 / 产品优先度 / 风格偏好），手动维护为主、自动沉淀为辅。

---

### M5 合规与强制约束（横切）

- 审查次数上限、风控闸门、违禁词/风险揭示语校验等**强制逻辑全部留在代码层**，不随"skill 化"迁移到 LLM 可控范围；skill/工具化的是"触发入口"，不是约束本身。
- 批量场景：审查为 workflow 内嵌步骤，批量不额外放水；失败标记"待处理"，不阻断整批。

## 4. 数据领域扩展（宏观）

以下领域需要数据模型扩展，**具体字段与存储结构在实现时确定**：

| 领域 | 扩展内容 | 目的 |
|---|---|---|
| 客户画像 | 任务数据、特征标签、生日 | 支撑任务体系与洞察标签 |
| 洞察 | 待确认洞察、洞察分析批次记录 | 支撑洞察沉淀与增量策略 |
| 调度 | 批量任务记录、定时配置 | 支撑定时任务与批量方案 |
| 权限 | 画像编辑字段白名单 | 行内硬数据只读约束 |

## 5. 技术落点（模块级）

| 模块 | 承担职责 | Pi SDK 边界 |
|---|---|---|
| 网关（pi-gateway） | 主对话 Agent（意图识别/工具注册/skill 加载）、方案 workflow、批量洞察 workflow、后台批量入口 | **全部基于 Pi SDK**（Agent 运行时、LLM 叶子、扩展注册） |
| 业务服务（backend） | 任务/洞察数据存储、策略规则、定时调度、批量任务编排入口、画像字段权限 | 宿主职责（Pi SDK 不覆盖：调度/存储/规则） |
| 前端（web） | 双界面布局、快捷按键、提醒区、taskType 筛选、方案双端同步、待确认交互 | 不涉及（消费网关 API） |

## 6. 关键风险

1. **混合模式纪律**：Agent 可能漏调工具/skill → 核心动作以快捷按键兜底 + 提示词明确工具清单
2. **skill 自动加载不确定性**：Pi 对 skill 为渐进式披露，模型可能不主动读取 → 关键能力用显式指令引导或注册为工具
3. **批量并发限流**：LLM API 并发限制未知 → 并发数配置化，需实测
4. **后台批量链路**：定时任务从业务服务到网关的后台调用需打通内部鉴权，网关需新增无实时流式的批量入口
5. **市场分析数据源**：本期空注入，外部接入需先定义接口契约（后续）
6. **LLM 洞察成本与质量**：全量分析 token 成本高（增量策略缓解）；洞察标签可能不准 → 待确认区把关 + 输出协议约束

## 7. 里程碑（任务调控依据）

| 阶段 | 范围 | 验证标准 |
|---|---|---|
| M0 基础准备 | 数据模型扩展、策略规则、批量入口 | 后端能力就绪，单测通过 |
| M1 双界面 | 布局重构、快捷按键、提醒区、方案双端同步、筛选 UI | 现有功能不回归 |
| M2 能力原子化 | 工具注册、批量洞察 workflow、skill 体系、意图路由 | 对话与按键均可触发全部核心能力 |
| M3 自动化 | 任务三层来源、组合筛选、定时三级链路、批量方案 | 早 9 点洞察-任务-方案闭环跑通 |
| M4 沉淀 | 洞察待确认（双源）、知识库沉淀、双通道触发 | 洞察→方案→接受→沉淀闭环完整 |
